# BUG-003 next() dereferences a null store when the counter block has to be extended

## Environment
- Firmware: S1 shared library `common/src/ppe_counter.cpp` as committed on feature/s1-shared-core; not run on hardware. Test hooks in the build: n/a (host test)
- Toolchain: host only (MSYS2 UCRT64, g++, mbedtls)

## Steps to reproduce
1. `PpeNodeCounter c(nullptr); c.resume(64, 64);` (valid image, block exhausted).
2. `c.next(&x);`

Reproducibility: always (needs a counter built without a store)

## Expected (spec 6.1, FR-17)
When the block must be extended and no storage is available, next() returns PPE_CTR_ERR_NVS, issues no counter and leaves its state unchanged, as it does for a failed write.

## Actual
next() calls store_->write_ceiling() on a null pointer and the program crashes.

## Analysis
- Root cause: cold_boot() checks store_ for null, next() does not.
- Why the host tests did not catch it: every test builds the counter with a fake store, except cold_boot() with a null store.
- Affected: no S1 caller. A future caller that builds a counter without a store would be.

## Fix
- PpeNodeCounter::next() returns PPE_CTR_ERR_NVS when the block must be extended and there is no store (`if (!store_ || ...)`). State is unchanged and no counter is issued.
- Approved requirement change needed? No
