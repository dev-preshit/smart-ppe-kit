## Environment
- Firmware: S1 shared library `common/src/ppe_filter.cpp` as committed on feature/s1-shared-core; not run on hardware. Test hooks in the build: n/a (host test)
- Toolchain: host only (MSYS2 UCRT64, g++, mbedtls)

## Steps to reproduce
1. `ppe_rx_filter(true, V_A1_ADV, 21, 1, V_KEY, nullptr);` (a well-formed advertisement and a null out pointer).

Reproducibility: always (needs a direct call with a null out)

## Expected
A null out pointer is refused without reading or writing anything, and the filter never reports PPE_RX_OK for it. It returns PPE_RX_DROP_LEN, the same fail-safe drop used for other unusable input.

## Actual
The filter decodes the payload into *out and crashes.

## Analysis
- Root cause: the step 1 check looks at pdu_is_nonconn_adv, adv and adv_len, but not out.
- Why the host tests did not catch it: filter_null_adv_is_drop_len passes a null adv, never a null out.
- Affected: no S1 caller. The hub in S3 will pass a real struct.
- Note: a null out is a programming error, so counting it as drop_len is a deliberate fail-safe choice, not a spec rule.

## Fix
- ppe_rx_filter() returns PPE_RX_DROP_LEN when out is null, before reading or writing anything (`|| out == nullptr` in the step 1 check). Behaviour for valid calls is unchanged.
- Approved requirement change needed? No
