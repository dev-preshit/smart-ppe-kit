## Environment
- Firmware: S1 shared library `common/src/ppe_crypto.cpp` as committed on feature/s1-shared-core; not run on hardware. Test hooks in the build: n/a (host test)
- Toolchain: host only (MSYS2 UCRT64, g++, mbedtls)

## Steps to reproduce
1. `uint8_t key[32] = {0}, payload[17] = {0};`
2. `ppe_hmac_tag(key, payload, nullptr);`

Reproducibility: always (needs a direct call with a null tag)

## Expected
A null output pointer is refused: ppe_hmac_tag returns false and writes nothing, as it already does for a null key or payload.

## Actual
The HMAC is computed, then the copy loop writes through the null pointer and the program crashes.

## Analysis
- Root cause: ppe_hmac_tag checks key and payload (inside ppe_hmac_sha256) but never checks tag.
- Why the host tests did not catch it: no test passes a null tag.
- Affected: no S1 caller. ppe_hmac_verify and ppe_sign_payload always pass a real buffer.

## Fix
- ppe_hmac_tag() returns false when tag is null, before computing anything. Behaviour for valid calls is unchanged.
- Approved requirement change needed? No
