## Environment
- Firmware: none (host tooling). Tools: pre-commit working tree. Test hooks in the build: n/a
- Toolchain: host only (Linux, Python 3.12, g++ 13, mbedtls 2.28.8)

## Steps to reproduce
1. `python tools/s1_run.py` with `unittest discover -s tools/tests -t <repo root>`.

Reproducibility: always

## Expected (SRS acceptance criterion)
TC-12 verdict reflects the firmware tests. The 25 host tests all passed.

## Actual
`ImportError: Start directory is not importable`; the runner counted that as a failed tool-test run and wrote TC-12 FAIL.

## Analysis
- Root cause: `-t <root>` makes unittest require `tools/tests` to be a package.
- Why the host tests did not catch it: it is a defect of the runner, not of the code under test. The runner treating a failed discovery as FAIL (not PASS) is the correct fail-safe.
- Affected requirements or other TCs: none.

## Fix
- Dropped `-t`; the tool tests insert `tools/` in `sys.path` themselves.
- Approved requirement change needed? No

## Regression
- Test added: `tools/s1_run.py` requires the tool tests to run (`Ran N tests`) and pass for TC-12; CI runs the same discovery command.
- Fails before the fix: yes. Passes after the fix: yes.
- Regression tier run: R0 (host suite + tool tests), PASS.

- TC-12 re-run on the committed tree: PASS, see `test_logs/S1/TC-12/`.
