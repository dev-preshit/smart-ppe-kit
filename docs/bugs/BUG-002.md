# BUG-002 resume() accepts an implausible RTC image and can lower the persisted counter ceiling

| Field | Value |

## Environment
- Firmware: S1 shared library `common/src/ppe_counter.cpp` as committed on feature/s1-shared-core; not run on hardware. Test hooks in the build: n/a (host test)
- Toolchain: host only (MSYS2 UCRT64, g++, mbedtls)

## Steps to reproduce
1. Fake NVS holding ceiling 5000 (the node already used counters up to 5000).
2. `PpeNodeCounter c(&nvs); c.resume(0, 0);` (zeroed RTC memory after a boot that was not a deep-sleep wake).
3. `c.next(&x);`

Reproducibility: always (needs a caller that passes a bad image)

## Expected (spec 6.1)
The counter never repeats or decreases. A state this class could not have produced is refused: next() returns PPE_CTR_ERR_NVS, issues no counter and writes nothing to NVS.

## Actual
resume(0, 0) marks the counter ready. next() returns counter 1 and writes ceiling 64 over the stored 5000. After the next reset, cold_boot() restarts from 64, so counters 65 to 5000 repeat.

## Analysis
- Root cause: resume() copies its arguments with no plausibility check and sets ready_.
- Why the host tests did not catch it: deep_sleep_resume_makes_no_nvs_write only uses a valid image, and the 1000 power-cut test never calls resume().
- Affected: not the node_test spike sketch (it checks the RTC-valid flag and the reset reason first); future callers in S2 and S4.
- Limit: a plausible but stale image cannot be detected inside the class. The caller must keep validating the RTC image and the reset reason.

## Fix
- PpeNodeCounter::resume() now accepts only an image this class can produce (64 <= ceiling <= 0xFFFFFFF0 and ceiling - 64 <= counter <= ceiling). Otherwise the counter is not ready and next() returns PPE_CTR_ERR_NVS, issues no counter and writes nothing.
- Header comment in ppe_counter.h updated. A stale but plausible RTC image is not detectable in the class; the caller still validates the RTC image and the reset reason.
- Approved requirement change needed? No
